# 0001. Build a Windows-only desktop app with Wails (Go + React)

- **Status:** Accepted
- **Date:** 2025-12-23

## Context

Focus Lock has to do low-level system work: terminate processes, edit the `hosts` file,
write registry policy, and run elevated in the background. It also needs a friendly UI with
block lists, schedules, a countdown and insights. The main users (students, professionals,
people with ADHD) are mostly on Windows, and each platform's blocking primitives are
completely different.

## Decision

- Write the backend in **Go** and the UI in **React + TypeScript + Tailwind** (Vite).
- Package them as one native executable with **Wails v2**, which renders the UI in WebView2
  and exposes Go methods to the frontend through generated bindings.
- Target **Windows only**. Platform-specific code lives in `*_windows.go` files, and
  `*_other.go` stubs keep `go build ./...` working on other systems so the pure logic can
  still be tested there.

## Alternatives considered

- **Electron.** Mature, but a much larger binary, and the system work would still need a
  native helper.
- **C#/.NET (WPF or WinUI).** The best fit for Win32, but a weaker UI toolkit for fast
  iteration, and a second language for any shared logic.
- **Tauri (Rust).** Similar model to Wails, but Rust would raise the bar for contributors
  on a solo project.
- **Cross-platform from day one.** macOS and Linux need different blocking mechanisms
  (pf/`/etc/hosts` with launchd, systemd), roughly doubling the enforcement work before
  the core idea was proven.

## Consequences

- One small exe holds both the UI and the enforcer (the same binary runs headless with a
  flag), which keeps installing and updating simple.
- WebView2 is a runtime dependency. It ships with current Windows.
- Go↔TypeScript bindings in `frontend/wailsjs/` are generated by `wails build`. Methods
  that return a JSON string avoid adding generated models.
- Supporting another OS would mean new enforcement backends behind the existing stubs, not
  a rewrite of the UI or the policy.
